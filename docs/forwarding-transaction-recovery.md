# 转发事务与恢复指南

## 能力边界

`lsec` 只管理当前 Linux 主机的 UFW、NAT、IPv4 forwarding 和本地状态，不包含 Xboard、证书、Hysteria2 或 VLESS 的安装逻辑。HY2、VLESS 在本文中只是端口用途示例。

“操作成功”表示脚本已按合法受管 marker 精确同步持久化 NAT 与 `iptables-save -t nat` 的实际规则、UFW 处于启用状态且完整路由定义唯一匹配、状态登记唯一，并确认运行时与持久化 IPv4 forwarding 均为启用。受管 NAT 使用字段语义比较，允许 iptables 后端调整单条规则内的参数顺序、补充 `/32` 或 `-m tcp/udp`，但接口、协议、来源、端口、目标、动作、marker 或同链规则顺序发生变化仍会判定不一致。UFW 路由同样按字段语义验证，允许 `ufw show added` 省略默认的 `from any` 或重排 `proto`，但不会放过真实字段漂移、重复 marker、未知子句或运行时规则缺失。发现只存在于 live NAT、但无法由当前状态或事务证明所有权的规则时，普通事务会停止并要求修复，不会静默删除。本机验证不等于端到端协议可达；还需要分别检查公网路由、云防火墙、落地服务监听、域名和应用配置。

## 中转机与落地机示例

假设落地机运行：

- HY2 使用 UDP 52350；
- VLESS 使用 TCP 52351。

中转机分别创建 UDP 52350 和 TCP 52351 到落地机的完整转发。启用 MASQUERADE 后，落地机看到的来源地址通常是中转机地址，因此落地机可以只允许中转机 IP 访问 UDP 52350 与 TCP 52351。若关闭 MASQUERADE，必须保证落地机回程路由经过中转机，且来源限制应按实际客户端地址设计。

这些名称不会写入脚本状态；运行时只保存协议、来源、网卡、端口、目标和 SNAT 选择。

## 创建与覆盖

新增完整转发时依次输入入口网卡、公开端口、落地地址与端口、出口网卡、来源、协议和 MASQUERADE 选择。TCP+UDP 属于一个批次，不会出现只成功一半的正常结果。

确认页提供：

1. 执行变更；
2. 仅运行前置检查；
3. 取消。

前置检查会验证输入、依赖和完整的暂存 `before.rules`。缺少组件时明确选择自动安装或取消；安装完成后从头重跑检查。

发现同参数受管规则时默认取消。选择覆盖后，还必须明确选中全部冲突旧规则；删除旧规则和重建新规则在同一事务内完成。

## 删除和 IPv4 forwarding

删除使用完整受管标记，不按模糊文本匹配。执行前必须确认状态、DNAT、按需存在的 MASQUERADE 以及 UFW 完整路由定义均唯一匹配；零条、重复或参数漂移都会停止并要求修复。多选删除属于一个批次。

删除最后一批规则时，只有脚本记录自己曾改变 IPv4 forwarding，并且没有发现其他登记或 NAT 转发用途，才会询问是否恢复原值。默认选择为“不恢复”。恢复也属于删除事务，失败会恢复删除前状态。

## 状态、事务和保护锁

状态目录为 `/etc/ufw/relay-manager`：

```text
forwarding.tsv
state.version
operation.lock
protected.lock
transactions/
backups/
```

所有系统变更共用一个排他锁。缺少 `flock` 时会先使用带 PID 的引导锁，经确认安装；检测到所属进程已退出的 stale 引导锁时会明确询问是否清理。事务日志记录准备、NAT、UFW、状态提交、验证和终态。事务日志 schema 3 还会独立保存首个失败阶段、错误代码、协议、marker、原因、预期、实际、证据采集警告以及回滚验证结果；回滚过程不会覆盖原始根因。启动时发现未完成日志会按快照自动恢复，既有 schema 2 事务日志仍可兼容恢复。

如果回滚无法验证，或发现受管 NAT 标记重复、错序、残缺，会写入保护锁。保护锁存在时，新增、删除、覆盖、安装和清理等变更被拒绝；只读安全检查、备份列表、诊断导出、恢复和修复入口仍可使用。失败提示会同时显示原始失败和具体回滚错误，便于区分“为什么操作失败”与“为什么没有恢复成功”。结构性锁可在管理员修复标记后通过维护菜单重新核对拓扑与全部受管层并清除。不要直接删除 `protected.lock`。

## 旧状态迁移

非空 `forwarding.tsv` 没有当前 `state.version` 时，脚本拒绝新变更。审计结果包括：

- `legacy-exact`：旧状态、NAT 和 UFW 唯一对应，可以事务迁移；
- `legacy-drift`：至少一层缺失或不唯一，需要人工核对；
- `malformed`：字段或输入无效，不能自动迁移。

自动迁移只处理全部为 `legacy-exact` 的集合，不会猜测、认领或删除漂移规则。

## 备份、恢复和清理

维护菜单可以列出备份、将选定备份作为新事务恢复、清理合规备份、导出诊断和修复保护锁。

成功快照至少保留最新 20 份，并保留 30 天。活动、失败、不一致、未验证、保护锁关联、未完成事务引用或 IPv4 forwarding 所有权引用的快照不会自动清理。清理必须明确输入备份 ID 并再次确认，保护锁期间禁止清理。

恢复会先备份当前状态，再协调目标 NAT、状态、IPv4 和受管 UFW 标记。恢复失败时回滚到恢复前；无法验证时进入保护锁。

每个发生回滚的事务会在对应快照的 `failure/` 目录尽力保存回滚前现场，包括结构化验证结果、`iptables-save -t nat`、`ufw show added`、`ufw status numbered`、IPv4 forwarding、失败时的 `before.rules` 和 `forwarding.tsv`。目录权限为 `0700`，文件为 `0600`。个别证据采集失败只记录警告，不会阻断回滚。

诊断文件权限为 `0600`，包含完整事务日志、回滚前证据、快照、保护锁、状态审计和 UFW 状态，便于人工恢复。
